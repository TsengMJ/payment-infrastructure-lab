# I-00.03 Docker Compose 本機環境

## 我原本以為

`pg_isready` 回成功就代表資料庫可以用了。官方 image 第一次啟動時，會先起一個只聽 Unix socket 的暫時 server 跑初始化，這時用預設方式（socket）呼叫 `pg_isready` 也會成功，但初始化還沒完成。

## 先想清楚的問題與答案

1. 問題：資料卷要不要持久化？測試和開發要不要用不同資料庫？
   答案：開發用具名 volume `payment-lab_postgres-data` 持久化，`make down` 不加 `-v`，資料保留。整合測試不共用這個資料庫：I-00.08 用 testcontainers 每次起拋棄式 Postgres，避免測試資料和手動 demo 資料互相干擾、也避免測試順序相依。所以這次 compose 只有一個 `payment_dev`。要清空時手動 `docker compose ... down -v`，刻意不做成 make target，避免誤刪。
   來源：[Compose volumes](https://docs.docker.com/reference/compose-file/volumes/)

2. 問題：映像版本要釘到哪個層級？
   答案：釘到 patch：`postgres:18.6`。`latest` 和 `18` 都會在某天自動換版本，同一個 commit 在不同時間跑出不同結果。major 升級（PG 18 → 19）的資料目錄不相容，必須手動 `pg_upgrade` 或重建 volume，絕不能讓標籤偷偷換掉。patch 升級時改這一行並寫進 commit 訊息。還沒釘 digest：個人專案的標籤被覆寫風險低，I-00.10 加安全掃描時再評估。
   來源：[Docker Hub postgres](https://hub.docker.com/_/postgres)

3. 問題：用 compose profile 區分「最小」與「含監控」嗎？
   答案：要，但這次不加。現在只有 Postgres，profile 沒有東西可分。I-00.09 加 OTel collector、Prometheus、Grafana 時放進 `observability` profile，`make up` 維持只起 Postgres。
   來源：[Compose profiles](https://docs.docker.com/compose/how-tos/profiles/)

## 我做了什麼決定，為什麼

- 決定：`POSTGRES_PASSWORD` 用 `${POSTGRES_PASSWORD:?...}`，compose 檔裡沒有預設密碼；缺少時 compose 直接失敗並說明要複製 `env.example`。
- 決定：本機密碼放在 git-ignored 的 `deploy/compose/.env`，範本 `env.example` 的值明寫 `local-dev-only`。根目錄的 `.env.example`（應用程式設定）留給 I-00.05。
- 決定：healthcheck 用 `pg_isready -h 127.0.0.1` 走 TCP，只有初始化完成後的正式 server 才會通過。
- 決定：PG 18 的 volume 掛 `/var/lib/postgresql`（PG 18 image 把資料放在 `/var/lib/postgresql/18/docker`），之後 major 升級可以在同一個 volume 內並存新舊目錄。
- 決定：port 只綁 `127.0.0.1`，不讓同網段的機器連進弱密碼的資料庫。
- 決定：`make up` 用 `--wait`，等到 healthy 才回傳，之後的指令不用自己輪詢。
- 放棄的選項與理由：把密碼寫在 compose 檔裡當預設值。方便，但這正是「常見陷阱」說的 commit 密碼，而且之後容易被複製到其他環境。

## 測試證明了什麼

- 沒有 `deploy/compose/.env` 時，`make up` 失敗並印出複製指令。
- env 檔沒有 `POSTGRES_PASSWORD` 時，compose 失敗：`required variable POSTGRES_PASSWORD is missing a value`。
- `make up` 在 healthy 後回傳；`docker compose exec postgres psql ... -c 'select version()'` 回 `PostgreSQL 18.6`，經 TCP 用密碼登入 `select 1` 回 `1`。
- 寫入一筆 probe 資料後連續兩次 `make down && make up` 都成功，資料仍在（count = 1），證明可重複執行且資料持久化。

## 用一句話向面試官解釋

本機資料庫用釘死 patch 版本的 image、走 TCP 的健康檢查與不進 repo 的密碼，讓 `make up` 在任何機器上都得到同一個可用的 Postgres。
