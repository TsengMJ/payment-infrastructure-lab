# I-00.05 設定與 secret

## 我原本以為

本機開發一定要在程式裡讀 `.env`，否則每個人都要手動 export。也以為資料庫連線字串可以有一個本機預設值，缺了就連 `localhost`。

## 先想清楚的問題與答案

1. 問題：哪些設定是 secret、哪些不是？要不要分開載入？
   答案：`DATABASE_URL` 是 secret，因為裡面有密碼。`HTTP_ADDR`、`SHUTDOWN_TIMEOUT`、`LOG_LEVEL` 不是。現在只有一個載入路徑：環境變數進同一個 `Config`，secret 用 `secret:"true"` 標記。不拆第二套載入；Vault / KMS 是 P16，現在拆只是兩份解析。
   來源：[The Twelve-Factor App: Config](https://12factor.net/config)

2. 問題：設定物件印到日誌時，secret 怎麼遮罩？
   答案：`Config` 實作 `slog.LogValuer`。寫日誌時 secret 欄位的整個值換成 `***`，不是只遮密碼那一段（host 也可能不該出現在日誌）。這次遮的是「已知的設定欄位」。任意物件的欄位名稱遮罩是 I-00.06。
   來源：[slog.LogValuer](https://pkg.go.dev/log/slog#LogValuer)

3. 問題：`.env` 檔要不要 commit？範例檔怎麼放？
   答案：不 commit `.env`（`.gitignore` 從 I-00.03 就忽略它）。commit 根目錄的 `.env.example`，裡面的密碼是 `local-dev-only`，只對齊本機 compose。程式的 `config.Load` 不讀檔。`cmd/api` 與 `cmd/worker` 在 I-00.07 用 godotenv 載入 `.env`，且不覆蓋已存在的環境變數；檔案不存在就繼續。
   來源：[joho/godotenv](https://github.com/joho/godotenv)（預設不覆蓋既有變數）

## 我做了什麼決定，為什麼

- 決定：缺 `DATABASE_URL`、URL 沒有 scheme 或 host、`SHUTDOWN_TIMEOUT` 不是正的 duration、`LOG_LEVEL` 不在 debug/info/warn/error，都啟動失敗，錯誤訊息含變數名稱。
- 決定：非 secret 才有預設值（`:8080`、`10s`、`info`）。secret 沒有預設值。
- 放棄的選項與理由：validator 套件。完成條件要的是訊息裡看得到缺了哪個變數，四個欄位用手寫檢查就夠。也放棄在 `config` 裡讀 `.env`，否則測試和正式環境都會偷偷吃到工作目錄的檔案。

## 測試證明了什麼

- `TestLoadMissingDatabaseURLNamesTheVariable`：沒有 `DATABASE_URL` 時錯誤含該名稱。
- `TestLoadRejectsMalformedDatabaseURL`：沒有 host 的值被拒絕。
- `TestLoadUsesDefaultsForNonSecrets`：只有 secret 沒有預設值。
- `TestLogValueRedactsDatabaseURL`：寫進 slog 後密碼與整個 URL 都不在，`database_url` 是 `***`，`http_addr` 仍在。

## 還不懂 / 之後要查

- `DATABASE_URL` 的 query（`sslmode`）算不算該分開驗證？錯誤的 sslmode 要到真正連線才會爆，I-00.07 的 `/readyz` 才看得到。

## 用一句話向面試官解釋

Secret 沒有預設值，缺了就啟動失敗並說出變數名稱；設定寫進日誌時，標記過的欄位整個變成 `***`。
