# I-00.01 Repo 骨架與 Go module

## 我原本以為

空的 module 跑 `go build ./...` 和 `go test ./...` 都會成功。實際上 `go build` 只警告 `matched no packages` 並回 0，`go test` 會印 `no packages to test` 並回 1。

## 先想清楚的問題與答案

1. 問題：Go module path 怎麼取？之後 P17 改成多 module 時會受什麼影響？
   答案：用 repo 的 import 路徑 `github.com/TsengMJ/payment-infrastructure-lab`。P17 在同一個 repo 用 `go.work` 加入新 module（例如 `.../services/ledger`），根 module 的 path 不用改，現有 import 不必整批替換。path 裡不放 `monolith`、`v1` 之類會過期的字。
   來源：[Go Modules Reference](https://go.dev/ref/mod)、[Workspaces](https://go.dev/doc/tutorial/workspaces)

2. 問題：Makefile 要提供哪些固定 target？
   答案：`build`、`test`、`lint`、`up`、`down`，全部宣告為 `.PHONY`（避免同名檔案讓 make 以為已是最新）。還沒實作的 target 明確失敗並說明在哪次迭代補上，不假裝成功。配方只用相對 repo root 的路徑與 `go`、`docker` 指令。
   來源：[GNU make Phony Targets](https://www.gnu.org/software/make/manual/html_node/Phony-Targets.html)

3. 問題：Go 版本怎麼釘住？
   答案：`go 1.27.0` 是最低語言版本，`toolchain go1.27.2` 是建議使用的工具鏈。本機 Go 低於 1.27.2 時（`GOTOOLCHAIN=auto`）會自動下載 1.27.2。`go` 和 `toolchain` 寫成同一版時，`go mod tidy` 會把 `toolchain` 行視為多餘而刪掉，所以 `go` 行寫 `.0`。
   來源：[Go Toolchains](https://go.dev/doc/toolchain)

## 我做了什麼決定，為什麼

- 決定：先建 `internal/platform/doc.go`（只有 package 宣告），讓 `go test ./...` 有套件可跑。
- 放棄的選項與理由：在 Makefile 忽略 `go test` 的非零結束碼。這會連真正的失敗一起吞掉。

## 測試證明了什麼

- `make build`、`make test`：在乾淨 clone 上成功。
- `make lint`、`make up`、`make down`：明確失敗並指出要在哪次迭代補上。

## 用一句話向面試官解釋

先把 module path、Go 版本與 `make build/test/lint/up/down` 固定下來，之後每次迭代都用同一組指令證明沒有弄壞東西。
