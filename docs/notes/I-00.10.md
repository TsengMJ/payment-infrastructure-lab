# I-00.10 CI 與 GitGuardian 誤報

## 我原本以為

GitGuardian 標到 compose 那一行，在 repo 放一份忽略清單就能讓 GitHub 檢查變綠。secret 掃描也該跟 lint 一樣用 `go tool` 釘版本。

## 先想清楚的問題與答案

1. 問題：哪些檢查失敗要擋 PR，哪些只警告？
   答案：全部擋。`make lint`（go-arch-lint 與 golangci-lint 的 govet、staticcheck、errcheck、unused、ineffassign）、`make test-unit`、`make test-integration`、`make vuln`、`make gosec`、`make secrets`。沒有只警告的項目，workflow 也沒有 `continue-on-error`。這個迭代要避開的陷阱就是為了綠燈關掉檢查。
   來源：[GitHub Actions workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax)

2. 問題：secret 掃描誤報時怎麼處理（允許清單要不要審查）？
   答案：CI 用 gitleaks，不把 GitGuardian 再包一次。允許清單只放在 `.gitleaks.toml`，每一條都要在同一行寫理由，所以會出現在 PR diff 裡。這次先掃過目前檔案：`local-dev-only` 與 compose 的 `POSTGRES_PASSWORD` 都沒被命中，清單維持空的，也沒有關掉任何規則。gitleaks 不接受一個沒有任何檢查的 allowlist 區段，所以檔案裡乾脆不放那個區段。GitHub 上的 GitGuardian App 不讀 `.gitguardian.yaml`。歷史 commit 裡仍有舊的那一行，要在已被標的那個 PR 的 GitGuardian check 上按一次 **Skip: false positive**，之後的分支才不會再因為同一段字失敗。
   來源：GitGuardian 檢查頁的 Skip，以及 gitleaks 的 allowlist

3. 問題：整合測試在 CI 裡怎麼啟動 Docker？
   答案：GitHub-hosted `ubuntu-latest` 自帶 Docker。`make test-integration` 用現有的 testcontainers 與 `payment-lab-atlas:1.3.0`，不另起 service container，也不使用 compose 的 `payment_dev`。CI 不啟動 Grafana。
   來源：I-00.08 筆記、[GitHub-hosted runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)

## 我做了什麼決定，為什麼

- 決定：compose 的 `POSTGRES_PASSWORD` 只寫欄位名，值從環境帶入。`make up` 與 `make up-observability` 在載入 `deploy/compose/.env` 之後，若密碼是空的就失敗，並印出「copy env.example」。
- 決定：golangci-lint `v2.15.0`、govulncheck `v1.9.0`、gosec `v2.29.0` 釘在 `go.mod` 的 `tool`。gitleaks 用映像檔 `ghcr.io/gitleaks/gitleaks:v8.30.1`，因為那個 module 的路徑仍是 `github.com/zricethezav/gitleaks/v8`，放進同一個 `go.mod` 後編不過。`make secrets` 加 `--no-git`，只掃目前檔案；刪掉 secret 之後這次掃描會過。若掃整段 git 歷史，刪檔也會一直紅，最後就會有人把檢查關掉。
- 決定：`toolchain` 升到 `go1.27.3`。`govulncheck` 在 `go1.27.2` 的 `crypto/x509` 報了 `GO-2026-6809`，而且呼叫鏈到 `http.Server.Serve`。
- 決定：`otelhttp.WithMetricAttributesFn` 已標成 deprecated，改由 handler 裡的 `Labeler` 加上 `http.route`。行為仍是路由模板，不是原始路徑。
- 放棄的選項與理由：把假 API key 的 commit 推上 GitHub 來當 CI 證據。GitGuardian 會掃那個歷史 commit，之後每個分支都紅，直到再標一次 test credential。

## 測試證明了什麼

- `make test-unit`、`make lint`、`make gosec` 通過。`make vuln` 對呼叫得到的程式碼回報 0 個漏洞。它另外提到有些被 import、但呼叫鏈碰不到的漏洞；預設的 symbol 掃描沒有因此失敗，也沒有把檢查關掉。
- `POSTGRES_PASSWORD` 為空時，`make up` 失敗並印出 `set POSTGRES_PASSWORD in deploy/compose/.env (copy env.example)`。有密碼時，`docker compose config` 帶入環境裡的值，檔案裡沒有那句錯誤訊息。
- 本機 commit 一個假的 GitHub token 檔 `secret-scan-fixture.txt` 後，`make secrets` 失敗（make 結束碼 2）。輸出已遮罩：

```
Finding:     api_key=REDACTED
Secret:      REDACTED
RuleID:      github-pat
Entropy:     4.803056
File:        secret-scan-fixture.txt
Line:        1
Fingerprint: secret-scan-fixture.txt:github-pat:1
leaks found: 1
```

- 接著 `git reset` 掉該 commit，沒有 push。工作區回到沒有那個檔案之後，`make secrets` 印出 `no leaks found`。GitHub Actions 還沒跑，因為這個分支還沒推；workflow 跑的就是這幾個 `make` 目標。

## 還不懂 / 之後要查

- GitGuardian 的 Skip 是記在他們那邊的「這一段字」，不是 repo 裡的檔案。若同一段字改了空白或換行，下一個分支會不會又被標成新的 incident，還要等按完 Skip 之後看一次新 PR。

## 用一句話向面試官解釋

PR 上的 lint、測試、漏洞與 secret 掃描失敗都擋合併；secret 允許清單寫在 PR 看得到的 `.gitleaks.toml`，掃描只看目前檔案，不看被刪掉的歷史。
